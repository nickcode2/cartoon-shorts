# Style notes: GuardTest look

Target: references/rick_frame.jpg. Bright, saturated 3D cell with a 2D cartoon card character. Remotion + three.js (R3F), 1080x1920, 30 fps, 150 frames.

## Files to reuse
- `src/GuardTest.tsx`: scene, lights, camera, textures, props, toon ramp, shadow patch. Copy this for a new shot.
- `src/guard.ts`: Canvas2D character drawing (`drawGuard`), shared constants (`CARD_W/H`, `METERS_PER_PX`, `SOLE_Y`), roller path (`rollerY`, `guardZ`).
- `src/Painterly.tsx`: `<Post frame />` post-process (ink edges, grain, bloom). Drop into any ThreeCanvas as the last child.
- `src/Root.tsx`: composition registration.
- Studio: `.claude/launch.json` entry `remotion-studio` (falls back to port 3001 if 3000 is busy). Do not render until asked.

## Lighting
- One warm directional sun (`#ffd9a0`, intensity 3.0, position about [-5, 3.4, 2.2]) from the side, `castShadow`, 2048 map, soft shadows, hard-looking.
- Cool blue ambient (`#7fa8ff`, 0.9). Caged ceiling light has a warm point light (2.5).
- `flat` canvas (no tone mapping). Walls and ceiling do not cast shadows; only props, pipes, bucket and the guard card do.
- Toon ramp: `MeshToonMaterial` with a 3-tone `gradientMap` (120/190/255). Use `RAMP` for all lit surfaces.
- Bloom is real (postprocessing). The bulb uses an HDR color (3.2, 2.9, 2.2) with threshold 1.0, so only the bulb glows.

## Painterly pass (keep it subtle)
- Ink edges: depth-based, dark brown-black `#1a0f12`, wobbling UVs, irregular width, dry-brush breaks, re-seeded about 10 fps ("boil").
- Shadow edges: `THREE.ShaderChunk.shadowmap_pars_fragment` is patched at module load to warp the shadow lookup with noise (guarded against double patching on HMR).
- Paper grain: fine grain + fibre + low-frequency blotch, about 3-6% modulation.
- Inverted-hull ink outlines on props (`InkBox`, `Pipe`) stay in addition to the post edges.

## Palette (GuardTest / CrisisShort only, superseded for new videos by "GLOBAL STYLE v3" at the end of this file)
- Bricks: light blue `#8fd3f0` upper, teal `#25b8c4` lower (below about 0.95 m), per-brick tint variation, ink mortar lines. Mortar is redrawn over the paint.
- Paint: pink `#ff6fb0`. Ink: `#120a14`.
- Ceiling `#2b5f93`, beams `#3a82d2`, floor `#b7d4e6`, drop cloth `#f1ead6`, door `#2f6fae` / `#3d86c6`, pipes `#a9c6e6`.

## Character rules
- 2D Canvas card on a plane, never a 3D model. Thick ink outline, bean head, thin limbs, round dot hands, oval shoes.
- Real shadow: two meshes. A visible card (`transparent`, `alphaTest` 0.02) and a hidden caster (`alphaTest` 0.5, `colorWrite` false, `castShadow`) using the same texture.
- Legs have a knee joint (thigh 150 px, knees push toward the wall). Hips drop up to 34 px and the knees bend when the roller is lowest. Feet stay planted. The hand is compensated so it stays on the painted path.
- Card yaw faces the camera at 55% so the roller stays on the wall. Texture is drawn at 2x.

## Camera
- Low angle looking up (height 0.35 to 0.55 m), wide lens (fov 64), pivot near guard chest.
- Slow push-in (distance 5.0 to 3.1 over about 85 frames), then a gentle 44 degree orbit from frame 70 on. Eased with smootherstep. (GuardTest only; new videos follow CAMERA RULES v2.)

## Gotchas
- Painted wall is a 2304x768 canvas texture (256 px/m) redrawn each frame from the roller path. Keep paint and card positions in sync via `guardZ` / `rollerY`.
- Toon plus bloom blows out easily: if the floor goes white, lower sun and ambient first.
- The in-app browser pane must be visible for screenshots.

## Rendering
- Render in Remotion Studio with "Client-side render", using the `CrisisShortSilent` composition (same video, no audio track; `<Html5Audio>` is not supported by the web renderer).
- Add the audio in editing: `public/mix.mp3` (loudness-normalised master), or the stems in `audio/stems/` (`voice.wav`, `sfx.wav`, `music.wav`, same length as the video, unmastered level about 4 dB below the master).
- Command-line renders on this Mac draw blank WebGL (headless Chrome). Do not use them for CrisisShort.
- Do not start renders unless asked.

## Reusable kit for new videos (single canvas)
- Use `src/kit/kit.tsx` (`SingleCanvasVideo` + `ShotSpec`, template in `src/kit/KitDemo.tsx`) for every new video. One WebGL canvas stays mounted for the whole video; shots only swap scene content, camera and light preset, so a cut cannot flash black. It also mounts a hidden copy of the next shot a few frames early and holds each frame until the scene has drawn (rAF + timer, works in the web renderer).
- Location changes: use `dip` (dip to a colour over N frames) instead of a crossfade, since only one scene is drawn at a time.
- `src/short/kit.tsx` and the CrisisShort composition are the old per-shot-canvas version: leave them as they are.

## After every client-side render
- The user puts the rendered MP4 in `out/`. Check it with ffmpeg blackdetect, no render needed: `python3 scripts/fix_black_frames.py out/<name>.mp4`.
- If it finds black frames, the script replaces each one with the previous frame (same frame count, audio copied untouched so sync is kept) and saves `out/<name>_fixed.mp4`. Report the frame numbers it fixed. If none, say so.


## Voiceover trim (future videos)
- Cut the warm-up so the first word starts about 0.4 s into `voiceover_clean.mp3` (CrisisShort used about 0.2 s). Cut point = first-word start in the original minus 0.4 s, which is 0.2 s earlier than before.
- The cut must still land in real silence after the warm-up: check with `silencedetect` that the 0.4 s lead-in has no warm-up sound in it. If the pause after the warm-up is shorter than 0.4 s, say so and use the longest clean lead-in available.
- Measure all sentence and word times on the new clean file, after the trim. The first shot starts at frame 0 and covers the lead-in: it is already framed and moving from frame 0, and its action starts on the first word.

## Framing (future videos)
- See "CENTER FRAME" at the end of this file. The old percentage-based framing rules no longer apply to new videos.


## DEFAULT STYLE for all future videos (approved: CharacterTest v2)
Reference implementation: `src/CharacterTest.tsx` (scene, lights, post, label) and `src/kit/hoodieMan.tsx` (character). This replaces the older toon/painterly look above for new videos. Stills of all expressions: `ExpressionSheet` composition.

- Limbs are single thick dark ink lines (`LIMB_W` = 21 px on the 600x1000 card), round dot hands, small oval shoes. Flat clothing colours with a hard cel-shade band.
- Ink outlines only on characters (drawn in the card canvas). The set has none: do not use the painterly `Post` or `InkBox`/`Box` ink hulls for the set.

### Framing
- Wide shots: full body visible, character about 50% of the frame height, plenty of set around him. CharacterTest: fov 50, camera 3.75 m to 3.25 m from the character, look target y about 0.92 to 0.95.
- Framing: see "CENTER FRAME" at the end of this file (check first, middle and last frame).

### Set and lighting (realistic, no toon ramp)

- Ambient occlusion: baked contact AO (dark gradient strips on the floor along shelf bases, `paintAO`) plus the lighting. Real SSAO was not used because the transparent character card breaks it (dark rectangle around the card).
- Depth of field and bloom via `ShotSpec.post` (`RealPost`): DOF focus = camera distance to the character, `worldFocusRange` 2.6, `bokehScale` 2.4; Bloom threshold 1.0; `ToneMapping` NEUTRAL; light vignette. Set `ownLights: true` on the shot so the kit does not add its preset sun/ambient.
- Glow on lights: HDR emissive fixtures (`Lamp`, colour 3.4/3.1/2.4) plus additive `Halo` sprites, floor light pools, sparkle glints.
- Real textures: tiled porcelain floor, painted walls, ceiling tiles, packaging labels (canvas-painted, Fredoka brand text). Products near the camera are instanced 3D boxes/cans/bottles; far shelves are textured planes.
- The set must extend past the camera on every side (floor, ceiling, walls, shelves long and continuous).

### Labels
- Pop-up labels ONLY when they add information: country names on maps, and key numbers/phrases from the narration (e.g. "72 HOURS", "3 DAYS"). Never as decoration or as scene titles (no "SUPERMARKET" over a supermarket).
- In-world signs that belong to the set (e.g. the "AISLE 7" hanging sign) are fine as set dressing.
- Style: plain white Fredoka text, thick black outline, subtle soft white glow. No yellow, no gradients, no colour.
- Component: `PopLabel` in `src/kit/PopLabel.tsx` (`text`, `pose`, `f`, `start`, `ready`, `focus`, optional `cy`, `hold`). Fredoka loads via `@remotion/google-fonts/Fredoka`: wait with `waitForFredoka` inside `useDelayRender` and pass `ready`.
- It is a screen-fixed plane at the character's focus distance (so DOF keeps it sharp), `depthTest` off, quick scale-up pop (`easeOutBack`, 9 frames). (Old videos only.)

### Gotchas
- Do not use `sed` with `/` in patterns here (mac sed); use the Edit tool.
- Studio's Browser pane must be visible for screenshots (`show_pane preview`).


## Render stability (MANDATORY for every new video)
Background: client-side render of CrisisShortV2Silent failed at random frames (347, 671) with "three scene drawn (frame N)", i.e. the draw gate never released (lost or stuck WebGL context). Cause: GPU resources only ever grew across shots (canvas textures from `makeTex`/`useTex`/`Person`/`LiveTex` were never disposed, the hidden next-shot copy was built twice, every `Box`/`Cyl`/`Ball` made its own geometries and materials twice for the ink hull). Fixes live in `src/kit/kit.tsx`.

### Rules
1. Dispose per shot. Anything you create outside JSX (`new THREE.*Geometry/Material/Texture`, canvas textures) must be created inside the shot component (`useMemo`, never at module level, never in the render body without `useMemo`) so the kit can free it when the shot ends. The kit disposes geometries and materials under each shot and every kit-created texture that no material references any more. Textures from `makeTex`/`useTex`/`LiveTex`/`Person` are tracked automatically. A texture made with raw `new THREE.CanvasTexture` is NOT tracked: use `makeTex`/`useTex`.
2. Reuse shared resources. `Box`/`Cyl`/`Ball`/`Plane` already share geometry and (colour-only) materials through a cache. For your own repeated props use `shared(key, make)` in kit.tsx instead of building one per instance. Never dispose shared objects (they are in `KEEP`).
3. No per-frame allocations. Do not call `new THREE.*`, `makeTex`, `document.createElement('canvas')`, or create arrays of geometries in code that runs every frame. Per-frame animation changes props only (position, rotation, scale, opacity). Redrawing an existing canvas (`LiveTex`, `Person`) is fine. Prefer instancing for large repeats.
4. Precompile. `GpuMonitor` compiles shaders for the current and the hidden next shot (`renderer.compile`), plus a probe of the common material variants at start. A shot with a new material type pays its compile in the lookahead frames, not on a visible frame.
5. Watch the numbers. Open the browser console during the first run: `[gpu] {"shot":N,"geometries":..,"textures":..,"programs":..,"freedTextures":..}` is logged per shot (also in `window.__gpuLog`). `geometries` and `textures` must stay roughly flat from shot to shot; a warning prints if they jump. If they climb, find what the shot creates and is not releasing before rendering.
6. Draw gate failures are logged with context state, `renderer.info`, last thrown error and GL error (`[drawgate] ...`), then the kit restores the context if possible, resets GL state and redraws (up to 10 tries, 4 s apart) before the delayRender timeout fails the frame. Report that console output if a render still fails.

### Chunked rendering (always, 300 frames per chunk)
Never render a whole video in one go. Client-side render cannot be scripted here (CLI renders draw blank WebGL), so do it chunk by chunk in Studio so a failure costs one chunk:
1. `python3 scripts/chunks.py <total_frames> <name>` prints the inclusive frame ranges (start-end) and which parts already exist. Example, 2112 frames: 0-299, 300-599, 600-899, 900-1199, 1200-1499, 1500-1799, 1800-2099, 2100-2111. General rule: part k covers frames (k-1)*300 to min(k*300, total)-1.
2. In Studio, composition `<Name>Silent`: Render > Client-side > Video, set Frame range to the part's start and end, Output name `<name>_partNN` (NN = 01, 02, ...). Reload the Studio tab between chunks so the GPU starts clean.
3. Put each MP4 in `out/`. If a chunk fails, re-render only that range (re-run the script to see what is `[MISSING]`).
4. When all parts exist: `python3 scripts/chunks.py --join <name>` (stream copy to `out/<name>.mp4`; add `--reencode` if the copy join glitches), then `python3 scripts/fix_black_frames.py out/<name>.mp4`.
5. Add the audio in editing as before (the Silent composition has none).


# GLOBAL STYLE v3 (MANDATORY for all FUTURE videos; do not touch or re-render CrisisShortV2)
Replaces any older palette, "many props and colors" or finish rule that conflicts. References: `references/Thumbnail_copy.jpg`, `references/123w.jpg` (deep indigo/purple shadows, one strong golden-yellow key, rose/coral gradients, orange rim glow on figures, soft haze). Code: `src/kit/finish.tsx` (`PAL`, `CLOTHES`, `Glow`, `RimLight`, `drawRimOnCard`, `paintedTexture`, `Book`, `SafeZoneOverlay` (now draws the center box), `SAFE` / `inSafe` (old videos only)).

## 1. Palette (replaced 2026-11-16: no fixed palette)
- There is NO fixed palette and no fixed hex list. Each video picks its own coherent palette of 4 to 6 hues (write it at the top of the shot notes / scene file) and keeps it consistent within the video. These main hues dominate every frame (ground, structures, buildings, water, sky); other objects stay soft and blend, with at most 1-2 accent colors per scene.
- More colorful than before. Vibrancy target 7 out of 10: clearly saturated and contrasty, not pastel, not neon (roughly medium-high saturation, strong value contrast between lit and shadow areas). If a frame reads as washed out, raise saturation and contrast; if it reads as neon, lower it.
- Lighting rules stay: shadows lean to a deep tinted hue of the video's palette, never grey or black; a warm key and a warm rim on figures; gradients in sky/background from the key color through the palette hues.
- Character clothing: any colors from the video's palette (plain solid colors, see CASTING RULES).
- `PAL` / `CLOTHES` in `finish.tsx` are the OLD violet palette, kept only so existing code compiles (KitTest6, CrisisShortV2). New videos define their own constants instead.

## 2. Painted finish v8 (REPLACES the old brush-stroke surfaces; reference: Marvel's "What If" animation)
- SURFACES ARE CLEAN. Walls, floors, seats, planes, props use clean, realistic colour textures (panel lines, seams, rivets, print, normal wear are fine). NO brush-stroke texture on any surface. One switch: `PAINTED_SURFACES` in `src/kit/finish.tsx` (false = clean; `paintedTexture` then returns a flat colour with a very soft top-to-bottom falloff).
- The painted feel lives ONLY in shadows and in ink lines:
  a) SHADOWS. Keep the soft shadows, baked AO and hemisphere light underneath. On top, shadow shapes are cut into three tones (lit, mid, dark) with hard, slightly brushy edges (cel-style). Surfaces: materials that set `defines={{PAINTED_SHADOWS: ''}}` get this in the shadow shader (`paintShadow` in `src/kit/kit.tsx`); materials without the define are unchanged, so older videos (CrisisShortV2) compile to the same shader. Characters: two tones of cel shadow with a wobbly hard edge drawn into the card on the shadow side (right and below, light from the upper left), clipped to head and body (the same idea is drawn inside the card canvas; `celShadow` lived in `glowChar.tsx`, now in `_archive/`, not yet ported to Ruri).
  b) OUTLINES. The character ink outline is black (`#120a14`, never another colour) with VARIABLE thickness: thicker on the shadow side and at bends, thinner in the light, with a slightly irregular hand-drawn edge (`inkOutline`: a filled ribbon, deterministic so it never shimmers). Limbs are black strokes whose width swells at the bend (stamped circles along the curve). Head and body outlines are drawn for every white character (Ruri still uses its own ink outline; the variable-width `inkOutline` lives in `_archive/src/kit/glowChar.tsx` if you want to port it).
  c) The coloured rim light and the glow rules (section 3) stay as they are.

## 3. Outlines and glow
- Characters keep the black ink outline (variable thickness, see 2b).
- Add a colored rim light on characters: `RimLight` behind and above, opposite the camera (orange `#FF7A4D` or rose), and/or `drawRimOnCard` into the card canvas. Rim must be visible as a thin warm edge on the shadow side. (Rim colour: warm orange/rose, or a hue from the video's own palette.)
- Glow on lights and key props: HDR emissive material (color above 1.0, bloom threshold 1.0) plus `Glow` sprites (additive, shared texture). Selective only. If a full bloom is needed use half-resolution bloom through `ShotSpec.post`.
- Glow stays cheap and follows Render stability: no per-frame allocations (animate opacity/scale props only), everything created inside the shot so the kit disposes it, and the `[gpu]` log (`geometries`, `textures`) must stay flat from shot to shot. Check it on the first run.

## 4. Framing
- See "CENTER FRAME" at the end of this file (the old edge and whole-object rules are gone).
- Debug overlay: append `?safe=1` to the Studio URL (or set `window.__safe = true`) and `SingleCanvasVideo` draws the center box (green dashed, with a centre cross; it reads `CENTER_BOX`, so it shows the current 15-85 / 12-85 box). Check first, middle and last frame of each shot with the overlay on before rendering. It is off by default and must be off for renders.

## 5. Font
- Pop-up labels always use Fredoka 700: white fill, thick black outline, subtle white glow (`PopLabel`).
- `PopLabel` now verifies the font with `document.fonts.check` after `waitForFredoka`. If Fredoka is not loaded it hides the label and logs `[font] Fredoka not available` instead of silently drawing a fallback. If you see that log, fix the load (do not render). Canvas-painted in-world text must also use `FREDOKA` from `PopLabel.tsx` (the `Book` title uses a plain `Fredoka` family name: pass the loaded font name when the title matters).
- Not verified in a render: this was not rendered (per instruction). Confirm in the first Studio preview that the label glyphs are Fredoka.

## 6. Props (see also "PROPS v8" below: every prop gets visible detail and a pleasant shape, cheaply)
- No placeholder shapes. Every prop is designed with depth and detail: bevels or rounded edges, thickness, secondary parts, texture, labels/markings, a base or contact shadow. Example: a book has cover boards, rounded spine, inset page block with page lines, a title on the cover, thickness and a bevel (`Book` in `finish.tsx`).
- A bare `Box`/`Cyl`/`Ball` is only a building block inside a prop, never the prop. Read the real object (see 7) and list its parts before modelling it.
- Reuse designed props through `shared()` / instancing for repeats (Render stability still applies).

## 7. Research (educational content)
- When a scene shows real things (maps, countries, flags, objects, places, animals, historical items), check them with WebSearch/WebFetch before modelling or painting: shapes, proportions, colors, positions, names, spelling, dates, numbers. Facts and visuals must both be right.
- Record the sources and key facts in a short note in the video's folder (or the scene file header).
- If web access is not available in the session, tell the user immediately, before building, instead of guessing.


# CAMERA, LABELS AND MAPS v4 (MANDATORY for all FUTURE videos; do not touch or re-render CrisisShortV2)
Code: `src/kit/camera.ts` (framing, moves, plan check), `src/kit/Label3D.tsx` (in-scene labels), `src/kit/MapKit.tsx` + `src/kit/data/*.ts` (real maps), `scripts/build_map_data.mjs` (data builder). ## A. Narration-driven camera
- Every sentence of the narration gets a TARGET (the person/object/place being talked about). The shot list has a column "narration -> target" (one row per sentence: line, frames, target, move, reason). Encode it as `PlanRow[]` and pass it through `checkPlan` (throws on a missing target or reason).
- The camera must frame that target at the moment it is spoken. Never zoom on something not mentioned. If the sentence names a new target, the move toward it starts so it is framed when the word is said, not later.
- Framing is computed, never eyeballed: see "CENTER FRAME" at the end of this file (`frameFocal` for a focal point, `frameTargets` for a group, `assertFramed` to verify at u = 0, 0.5 and 1).
- Two characters side by side: pass both as targets so both are framed as a group. Never crop a face in half by accident.

## B. Professional camera moves [SUPERSEDED by CAMERA RULES v2: only locked-off and straight push-in by default; truck/orbit/diagonal/parallax only on explicit request]
- One clear move per shot, each with a stated reason in the plan: `truck` (lateral dolly), `pushIn`, `pullOut`, `diagonal`, `parallax`, `orbit`, or `holdDrift` (calm beat only). - Push-in to emphasise what is being said, pull-out to reveal or give context, truck/parallax to follow motion and show depth, slow orbit (under about 40 degrees) for a place or object being described, diagonal for a combined reveal.
- Wider shots when the viewer must understand what moves (vehicles, ambulance, props such as a book): pull back enough that the viewer still recognises it; the focal point stays in the center box for the whole move.
- Moves obey CENTER FRAME: check the first, middle and last frame.

## C. Labels inside the scene
- Labels live in the 3D environment, anchored to the thing they name, and follow the camera. No fixed overlay at the top for new videos. Use `Label3D` (`text`, `anchor` world point, `pose`, `f`, `start`, `ready`, optional `rise`, `px`, `slide`, `hold`, `lift`). Example: a country name rising out of the map anchored at `countryAnchor(...)`.
- Animation: rises out of the anchor with a scale pop (easeOutBack, 12 frames) and optional slide-in. Billboard to the camera, on-screen text height `px` (default 150) so it stays readable at any distance.
- Font: Fredoka 700, white, thick black outline, subtle white glow. Same font check as `PopLabel` (hidden and logged if Fredoka is not loaded).
- Labels ONLY when they inform: country names and key numbers/phrases from the narration. Never decoration, never scene titles. The label must sit inside the center box while it is shown.
- `PopLabel` (screen-fixed) stays only for old videos.
- Render stability applies: texture drawn once (not per frame), no per-frame allocations, disposed with the shot.

## D. Maps
- World, continent and country shapes use real outline data, never hand-drawn guesses. Data: Natural Earth via world-atlas TopoJSON, decoded by `scripts/build_map_data.mjs` into typed files: `countries110.ts` (all 177 countries, world views) and `europe50.ts` (19 European countries at 50m, zoomed views; the UK is real 50m shape). For other regions run `node scripts/build_map_data.mjs 50m src/kit/data/<name>.ts "Country A,Country B"`.
- Use `WorldMap` (`data`, `view` {lon0, lat0, k}, `highlights` {name: {color, h}}, `only`, `clip`): countries are extruded in 3D, painted in the palette (land blue-violet, indigo sides, highlights in rose/lilac/key colors), merged per class so geometry count stays low. North is up (-z). Use Natural Earth names ("United Kingdom", "Czechia"); an unknown name throws.
- Natural Earth includes overseas territories (e.g. France: French Guiana). Always pass `clip` for regional views.
- Highlighted countries must look like the real shape and sit in the right place relative to neighbours and coasts. Before using a country check it in the preview against a reference image (search the web), including the map orientation, and check the neighbours that appear around it.
- If web access is ever missing, say so first and use simplified outlines, flagged as approximate in the shot notes.


# ANIMATION v5 (MANDATORY for all FUTURE videos; do not touch or re-render CrisisShortV2)
Character design is unchanged (thick ink stick limbs, ball hands, oval shoes). Only motion changes. Code: `src/kit/motion.ts` (walk, idle, phone, pickPlace, cardSpace, flap), `src/kit/collide.ts` (keep-out zones, path checks, car entry), `src/kit/reactions.ts` (looks, nods, smile, blinks), `src/kit/hoodieMan.tsx` (new optional `ManPose` fields), `ExpressionSheet` (hair-check row). Omitted new fields = the old static pose, so old shots are unaffected.

## ManPose motion fields (card px, 600x1000, ground y 942)
`feet` (absolute ankles, IK legs), `hands` (card-space targets, IK arms; null = hang), `body {dx, dy, lean}`, `face` (walk direction, toes lead), `nod`, `headRoll`, `blinkPhase`, `grip`, `phone`. Always build them with the helpers below, not by hand.

## 1. Walking
- Use `walk(dist, {stride, dir, scale, intensity})`. `dist` = metres travelled, the integral of the SAME ground speed that moves the card in the world. Phase comes from distance, so the planted foot moves back exactly as fast as the body moves forward: no sliding. Never drive a walk from time alone.
- The cycle has: weight shift (sway toward the stance foot), hip and torso lean, opposite arm/leg swing, foot lift on the swing leg with toe tilt, body bob on the classic 4 key poses per step (contact and passing mid height, LOWEST at 'down' 1/8 cycle after contact, HIGHEST at 'up' 3/8). Stride default = 0.75 x the leg length in metres (`defaultStride(rig)`, about 0.4 m for these cartoon legs; a 0.62 m stride made the foot reach 1.10 x the leg and slide, see the fix below); timing reference is about 0.5 s per step (12 frames at 24 fps, `STEP_SEC`), so ground speed is about stride / 0.5 s. Slower or faster walks must change the stride, not just the speed. Always pass the character's `rig` (`RIG_HOODIE`, `RIG_GLOW`; RIG_GLOW is only the name of the limb rig Ruri uses) to `walk`, `holdPhone`, `standFeet`.
- Start and stop: ramp `intensity` 0 to 1 over at least 0.5 s with `easeInOut` (and mix `STAND_FEET` / `idle`). Standing characters use `idle(t, seed)` (weight shift, breathing), never a frozen pose.
- For exact plants the walk direction should be roughly across the screen (truck/orbit shots) and the card `yawK` 0. A walk straight toward or away from the camera shows foot lift only: slow it down and prefer a diagonal/lateral shot.
- Timing: no snappy, robotic actions. Use at least `MIN_SEC` (reach 0.5 s, lift 0.4, place 0.45, retreat 0.45, turn 0.4, door 0.6, lower 0.5, step 0.5). Every action has anticipation, ease in/out and a short overlap with the next one. More frames per action is always better than fewer.

## 2. Hands and objects (no teleporting)
- Use `pickPlace({start, rest, from, to, carry, lag, dur})` in world space. Sequence: anticipation (small pull-back), reach (ease to a pre-grasp point above the item, then settle), grip (ball hand squeezes via `grip` only after the arm has settled: the hand closes last), lift (slight body `dip` before it as anticipation, bigger for heavy objects), carry, lower, release, retreat. Staggered timing: head leads, arm, then torso. `weight` 0..1 sets how far the object drags behind the hand. The object blends onto the hand at grip and off it at release, follows with a natural lag (`lag` 0.07 s, evaluated as the hand path in the past), and gets a small settle bounce. The state returns `hand`, `grip`, `obj`, `holding`, `phase`, `lean`.
- Aim the arm with `cardSpace(p, s, yaw).toCard(handWorld)` then `handSlot`. Add `lean` to `body.lean` during the reach.
- Objects never appear, vanish or jump: before the grip the object sits where it was, after the release it sits at the target (shopping bag, counter, cart). If an object must enter or leave the scene, it does so through a visible action (taken from a shelf, dropped in a bag), never a cut.
- Durations below `MIN_SEC` throw. Example: items from a shelf to the cashier counter = one `pickPlace` per item, the next `start` overlapping the previous retreat.

## 3. Holding a phone
- Use `holdPhone(t, side, k, seed)`: forearm raised in front of the chest, ball hand at the phone's lower edge, wrist tilt about 10 degrees with slow variation, small idle sway (x 3 px, y 2.5 px), head dips toward the screen (`nod`), hand squeezes slightly. Ramp `k` 0 to 1 over at least 0.5 s when raising or lowering the phone. Never a stiff, static arm.

## 4. No clipping, keep-out zones
- Every solid object a character could touch gets a `Zone` (`carZone`, box or circle) in the shot setup: cars, doors, counters, shelves, carts, walls of buildings. Every character path (ground x,z over time) is checked with `assertPathClear(label, path, t0, t1, zones, radius, allow)` at shot setup; it throws with the time, zone and position of the first overlap. Fix the path (or use `slideOut` for brushes) before rendering. Body radius 0.28 m.
- Allowed contact only through `allow` windows (getting into the car, sitting at a counter), never as a shortcut.
- Entering a car: `carEntry({start, door, seat, zone})` = walk to the door stand point, door opens by the handle (0.7 s, drive `Vehicle.doorOpen`, `reach: 'outer'`), character turns (0.45 s), ducks head and torso to clear the frame and lowers (0.6 s, `duck`, `crouch`), moves in and settles (0.7 s), reaches back to the inner handle and pulls the door shut (0.6 s, `reach: 'inner'`). The beats come from the vehicle-animation reference; its durations are NOT sourced (ours are estimates, untested). Its `allow` window opens only after the lowering. The character card sits inside the car so the solid body occludes the lower half; the window must show glass.
- Also check hands: a hand target inside a zone (reaching through a counter) is clipping too.

## 6. Reactions
- Two characters talking: use `listener(t, {speaker, self, camRight, from, to, nods, smileAt, index})`: head turns toward the speaker (`lookToward`, eased 0.45 s, starting with the speaker's first word: listeners react, they do not anticipate), small nods (`nod`, 10 px, 0.5 s) DELAYED and placed at the speaker's pauses (0.2 to 0.4 s after a phrase ends), not on stressed words, a gentle listening tilt (`listenTilt`), a soft smile (`smile`: neutral blended 55% toward smug, never the full smirk) that follows almost at once (0.25 s ramp), staggered blinks (`blinkPhase(index)`; no two characters blink together).
- Mouth sync: `speak` comes from the real voice, measured once into a per-frame series, then `flapFromSeries(series, frame, lead = 1)` (smoothed over 3 frames, noise gate, 12 mouth steps, leads the audio by 1 frame). A silent character never moves their mouth. Speaker head nods/rolls on stressed words are NOT backed by a source found yet: use sparingly and look them up before relying on them. Blink interval (3.5 s) is also unsourced.
- Heads always turn toward what they look at (the other character, the object being handled); no dead stares into the camera mid-scene unless it is a deliberate beat.

# CENTER FRAME (MANDATORY for all FUTURE videos; do not touch or re-render CrisisShortV2)
Replaces every earlier framing rule (percentage zones, whole-object fit, close-up fill). Code: `src/kit/camera.ts` (constants `CENTER_BOX`, `FOCAL_TOL`, `HEAD_EDGE_MARGIN`, `GROUP_FIT`; `frameFocal`, `frameTargets`, `closeUp`, `focalInBox`, `headInBox`, `assertFramed`, `checkPlan`). Overlay: `?safe=1` draws the box (`SafeZoneOverlay` in `finish.tsx`).

1. FOCAL POINT. Each plan row declares a focal point (`PlanRow.focal` = `{p, r, name}`): what the narration is talking about (a face, a window, a cup, the crack, the nose of the plane). It must sit inside the central box, about 15-85% of the frame width and 12-85% of the frame height (`CENTER_BOX`, widened 2026-11-16: the old 30-70 / 25-70 box made characters too small and far), never touching the very edge.
2. HEADS. A speaking or reacting character: the whole head is inside the central box and never touches or crosses the frame edge (`Focal.head`, or `PlanRow.heads`; checked by `headInBox`). A head may be cropped only on purpose, in an extreme close-up where a face part (the eye) is the focal point (`Focal.crop`).
3. EVERYTHING ELSE may be cropped by the frame at any zoom: the rest of the plane, the room, big props. Narration about a plane's window: frame the window, not the whole plane.
4. STILL READABLE. No zoom so tight that the subject is unrecognisable. Never crop a face in half by accident: two characters side by side are framed together, centred as a group (`frameTargets` without `focal`).
5. SCENERY continues beyond the camera on every side the camera can reach (no empty edges).

Code behaviour:
- `frameFocal(focal, {fov, yaw, pitch, span})` puts the focal point on the centre of the box; `span` = fraction of the box height covered by the focal circle (diameter 2 r), free zoom.
- `frameTargets(targets, opts)`: without `focal` it is GROUP framing (centre the group on the box, fit its bounding box into `GROUP_FIT` x (1 - margin) of the frame). With `focal` it delegates to `frameFocal`.
- `closeUp`: fill is free; `fill` / `objectFill` (fraction of FRAME height) are informational; `inSafe` = focal point in the box.

# CAMERA RULES v2 + SPEED AND COST OVERRIDES (calm-camera rules 1, 2, 12 and the 'locked-off' idea are REPLACED by CAMERA RULES v3 at the end of this file; the rest still applies) (was MANDATORY for all FUTURE videos; do not touch or re-render existing videos)

## Rules
1. [SUPERSEDED by CAMERA RULES v3: every shot has ONE smooth S-curve 3D move, arcs up to 40 deg are allowed] CALM CAMERA. Every shot is locked-off (tiny slow drift, `lockedShot`) or a slow straight push-in along the camera's own axis (`pushIn(from, to, {duration, ease})`; a push that is off axis by more than 0.05 m throws). No orbits, arcs, rotation or crane moves. An orbit only if the user asks, at most once per video.
2. MOTION COMES FROM THE SCENE: character acting, props, light changes, glow, cracks, debris, dust, a hand or object entering from the edge. The camera holds.
3. WIDE LENS, CAMERA CLOSER (changed 2026-11-16, was 15-30%). Wide fov (56-66 in 9:16), floor and ceiling both visible in wide shots, strong perspective lines, full-body character about 30-45% of frame height (`WIDE_BODY_FRAC`, measure with `bodyHeightFrac`), camera height at chest or lower. Use MORE MEDIUM SHOTS so the video feels more dynamic: `checkPlanV2` warns when fewer than 30% of the framings are medium (`V2_LIMITS.minMediumShare`). Heads still never touch the frame edge.
4. SHOT LADDER per location: wide -> medium -> close/insert, on the same axis (push straight in or cut closer on the same line). `checkPlanV2` warns when a close/insert follows a wide directly ONLY if that location has no medium shot at all.
   PUSH ALIGNMENT (2026-11-16): `pushIn` keeps the look point fixed and moves the camera along its own axis, so a subject that is off the axis drifts toward the frame edge as the camera closes in (KitTest6: the head left the left edge on frames 72-82). A straight push must stay on the focal point's axis. Give the plan row `push: {from, to}` (the same poses passed to `pushIn`); `checkPlanV2` (via `pushWarnings`) warns when the push moves the focal point or a head out of `CENTER_BOX`, and says how to fix it: place the subject on the camera axis (aim the look point at it, e.g. `frameFocal`) or shorten the push.
5. NAMED ANGLES, REUSED (`defineSet(set, {name: Pose})`, `angleOf`, `cutTo`). A recurring place always uses the same framing. Prefer a hard cut back to an angle already built over a new one.
6. THE CAMERA FRAMES THE SUBJECT OF THE CURRENT NARRATION WORD (object, wall, result), not the person; the character may walk out of frame.
7. NO FOLLOW CAMERA. When a character changes place, cut to a camera already waiting there and let them enter. Sequence: wide of the room -> door from the side -> inside the next room.
8. NARRATED SMALL OBJECTS: `insertCloseUp(focal, {from, fill, foreground})` = straight-on tight close-up (reach it with `pushIn` on the same axis, hold 1-2 s, `cutTo` a wider angle). Part of the character (face/hand) cropped at the frame edge, background blurred. The focal point is in the central box, the rest of the object may be cropped. Large or moving things (vehicles, maps, rooms, buildings) stay wide.
9. FOREGROUND LAYER on most medium and close shots: a dark cropped shape near the camera (shoulder, guard's back, door frame, hand). `insertCloseUp`'s `foreground` returns the placement (one cheap shared dark plane, tinted `#1E1448`); render it with `shared()`.
10. EMOTION PEAKS: slow push-in to the face (medium -> close over about 3 words), then a HARD CUT to a wide for the impact, FX in the scene. A short camera shake only at the impact.
11. TRANSITIONS: hard cuts inside a location. `dissolveTo(angle, {duration: 0.3-0.5})` only for a location change or time jump (the single-canvas kit draws one scene at a time, so it is the kit's `dip`, not a true crossfade). A new big location may use one continuous descending aerial move.
12. [SUPERSEDED by v3: all moves use `easeS` (smootherstep)] EASING: pushes use `easeTrapezoid` (quadratic ramps in and out, constant speed in the middle, no bounce or overshoot). No sudden speed changes except the rule 10 shake.

## Speed and cost overrides (win over the old rhythm numbers)
- RHYTHM: one framing change about every 6-10 narration words (about 20-25 framings for a ~195 word script). A framing never lasts more than 12 words and never changes faster than every 3 words.
- REUSE: at most 3 locations per video, at most 3 named angles per set.
- At most 4 close-up props per video. Characters reuse a small set of actions (walk, stand, talk, one or two reactions). Do not build a new prop or animation for one shot if an existing one works.
- Keep the build simple and cheap; when in doubt choose the simpler option and tell the user.
- `checkPlanV2` throws if: an orbit is used without the user's request (or twice), a framing lasts more than 12 or fewer than 3 words, more than 3 angles in a set, more than 3 locations, more than 4 close-up props, a moving character is tracked (`tracksMover`) instead of cut to, an insert has no prop name, or the CENTER FRAME focal point/head data or the reason is missing. It warns when the average framing is outside 6-10 words.
- PlanRowV2 columns: line, from, to, words, set, angle, shot (wide|medium|close|insert), move (locked|push|cut|dissolve), target, focal, heads, why, prop, orbit, tracksMover. A framing = consecutive beats with the same set, angle and shot where later beats are `locked`.

## Blur and depth of field
- Real depth of field EXISTS in the kit (`src/kit/Dof.tsx`, `FocusDof`, half-resolution bokeh, one pass). Use it for rules 8 and 9: `insertCloseUp(...).dof` gives the `focal` and `r` to pass. No fake blur and no new full-screen blur is needed. If the foreground plane looks too sharp, rely on DOF; keep the dark tint only as a cheap extra.

# CAMERA RULES v3 (2026-11-16, MANDATORY for ALL future videos; REPLACES the calm-camera / no-orbit / no-arc rules of v2)
Why: Ricks Clips is a real 3D set with a camera that moves through it (parallax); only the head and torso are 2D cards, arms, legs, hands, feet are unlit dark 3D tubes. The dynamic comes from the camera. Code: `src/kit/camera.ts` (section "CAMERA RULES v3"), card tilt in `rickRig.tsx` (`cardTilt`).
KEPT from v2: wide lens + far camera, 3-step ladder per location (wide, medium, close), 3-4 named angles per set reused, camera frames the subject of the current narration word, no follow camera (cut to a camera already waiting), narrated small objects get a tight close-up with a cropped foreground layer, foreground layer on medium / close shots, emotion peak = push-in then hard cut to wide, dissolve only for location / time jumps, rhythm (framing change every 3-5 words, never the same framing more than 6 words).
1. Every shot has ONE smooth 3D camera move; never frozen; no stacking of move types (a sequence of two moves is fine).
2. EASING = S-curve: `easeS` (smootherstep), slow-fast-slow. Never linear, no bounce, no overshoot.
3. Vocabulary: `pushInV3` (8-20 %), `arcIn` (push + orbit 15-35 deg, max 40), `craneTiltDown` (rises and pitches down 30-80 deg), `craneUp` / `craneDown`, `truckV3` (1-2 units + slight yaw), `pullBack`, `dutchDeg` 5-8 on about 1 shot in 4, a short `shake` only at an impact. No whip pans, no 360 spins. All are views of `moveV3(pose, {push, yawDeg, pitchDeg, dx, dy, tilt, dutchDeg, shake, endAt})`.
4. Foreground + parallax: medium / close shots keep something near the camera (cropped, slightly dark / blurred); wide shots need depth layers in the set.
5. Hero objects (can, coin, box, door, desk, bag, poster board) are real 3D models with top, rim, thickness and label, never flat cards.
6. 2D cards under a moving camera: yaw follows the camera (profile art takes over by torso yaw), and the card AND its limb tubes tilt toward the camera by 60 % of the camera elevation, clamped to 35 deg (`cardTilt`), so no card shows a thin edge.
7. Framing: faces may be cropped or fill half the frame in close-ups; the safe zone applies to the key subject, not to the foreground layer.
8. `checkPlanV3(rows, strict)` fails on: no move, linear ease, yaw over 40, stacked move types, a framing over 6 words, more than 4 named angles per set, a tracked moving character, a flat hero object.
COBRA_EFFECT applies the table of moves in `src/CobraEffect.tsx` (ENTRIES); not done there: the foreground layers (rule 4) and 3D poster boards (rule 5), because looks were not to change; framing lengths exceed 6 words in several entries (approved timings kept).


# CAMERA RULES v3.1 + QA GATE (2026-11-16, MANDATORY for all future videos; UPDATES v3)
- REVERSED: "no follow camera". - HEAD NEVER CUT: unless the shot kind is close / insert, the framing box [w, h, d] around the focus fits the frame with >= 5 % margin. - SNAKES: yaw follows the velocity (head leads), `target` aims the head (strike pose + lunge), snakes that emerge start inside (head behind the door), travelling sine wave in the vertex shader (follow-the-leader is approximated by a wave on a straight tube, not an exact path trace). Head = ellipsoid centred on the tube tip centreline, overlapping the tip (gap 0).
- QA GATE: `src/kit/qa.ts` `runQA`. Run: open Studio with `?qa=1` (CobraEffect) and read `window.__qa` / console "[qa] PASS|FAIL": focus centre in CENTER_BOX, bbox margin, occlusion, camera inside geometry, angle rules, snake rules, camera moves, S-curve, no flat hero object. # CHUNK RENDER TOOL (2026-11-16, KIT tool for ALL videos; replaces the manual "Chunked rendering" steps above, `scripts/chunks.py` stays as a fallback)
Code: `src/kit/ChunkRender.tsx` (composition `chunk-render`, registered in `Root.tsx`), `scripts/join.mjs` (`npm run join`), `src/kit/ChunkSelfTest.tsx` (70-frame 2D test clip, composition `ChunkSelfTest`).
## Render
1. Start Studio (`npm run studio`, `remotion-studio` entry), open `http://localhost:<studio port>/chunk-render` in Chrome (port 3000, or 3001 if 3000 is busy). Keep that tab visible.
2. Pick the composition by name (dropdown, read from Studio's own list: any new video appears automatically, no registry). Total frames is prefilled (editable), chunk size 300.
3. "Pick folder" once: choose the video folder (e.g. `COBRA_EFFECT`). Chunks go to `<folder>/chunks/chunk_001.mp4, chunk_002.mp4, ...` plus `chunks/manifest.json`. The folder is remembered; after a restart press "Use saved: <folder>" (one permission click).
4. Start. It renders with `renderMediaOnWeb` (same client-side WebCodecs renderer and defaults as Studio's dialog: mp4, quality high, keyframe 5 s, muted), one chunk after another. Between chunks: 2.5 s pause, `gc()` if Chrome exposes it, and a `[gpu]` line per chunk (shots logged, geometries, textures, programs, peak values, JS heap) in the page log and console. A failed chunk is retried once after 6 s, then it stops with the chunk number.
5. Resume: on load/Start it reads `manifest.json` and keeps every chunk whose file exists with the recorded size; it shows "Resuming from chunk N" and renders only the missing ones. Files are written through a swap file, so a crash never leaves a half chunk under its final name. If the manifest was made with other settings (composition, total, chunk size) it refuses and tells you to delete `<folder>/chunks`.
6. Page keeps a tab-visible warning (turns red when the tab is hidden), requests a screen wake lock (re-requested when the tab becomes visible), and warns before closing the tab while running.
7. Browsers without the File System Access API: automatic downloads named `<Composition>_chunk_001.mp4`, ... plus `manifest.json` at the end, into the browser's download folder (Chrome: ~/Downloads). Move them into `<folder>/chunks/`. No automatic resume there: set "First chunk".
## Join
- `npm run join` (newest folder with `chunks/`), or `npm run join -- COBRA_EFFECT`. Checks every chunk exists, counts the frames of each chunk with ffmpeg against the manifest, joins by stream copy (no re-encode) into `<folder>/<folder>_silent.mp4`, then counts the joined file and compares it with the total. Add `--reencode` if the copy join glitches at a boundary; `--frames N` when there is no manifest.
- No ffmpeg: `npm install --save-dev ffmpeg-static` (no Homebrew; the script finds it by itself). Then `python3 scripts/fix_black_frames.py <joined file>` as before.

## 3. HATS AND HAIR STAY ON THE HEAD DURING ALL HEAD MOTION (yaw, pitch, roll)
- Bug seen: when a character looks up / tilts or the head moves, the hat floats off and the hair fringe becomes a flat dark block across the face. Cause: the 3D gear only knew roll and yaw, there was no pitch; any pitch drawn on the flat face card (or a camera looking up / down) moved the face and not the gear.
- RULE: hat, cap, hair and clips are children of the SAME head pivot (`HeadGear`) and follow ALL head motion: yaw (group rotation), roll (`headRoll` + lean + bounce rock), pitch (`RickPose.headPitch`, rad, + = looks up, limited to 40 deg), bobbing and body lean (pivot position `headCard`), reaction head shakes. The hat stays seated on the crown (brim line at the brow with the designed overlap) at every angle. Hair fringe / bangs sit only ABOVE the brow line and never cover eyes, eyebrows, nose or mouth of the face card; a hair mesh that crosses the face at any angle must be shrunk or reshaped. Hat and hair never intersect.
- HOW PITCH WORKS (`pitchAffine` in rickRig.tsx): the head art is flat, so a nod is one shared affine, never a true 3D rotation of the gear over a flat card (that is what broke it). The HEAD UNIT (silhouette, 2D gear, 3D hat / hair meshes) is foreshortened toward the neck, y' = ry + (y - ry) cos(pitch); face features additionally glide by `PITCH_UP` 0.05 ry (up) or `PITCH_DOWN` 0.10 ry (down) times sin(pitch), so brows never reach the brim or the fringe. Use `pose.headPitch`; omitted = 0 = identical to the old pose (old videos unchanged). Troll faces are not pitched (not done). Ruri (`hoodieCurved.tsx`) draws hair and cap into the card in the same transform as the head (`nod`, `headRoll`), so they follow by construction; not changed and not checked here. Values are estimates, not from a reference.
- QA (src/kit/headgear.tsx, re-exported by qa.ts): `motionReport` / `motionRow` check pitch -35, -20, +20, +35 and roll -20, +20 combined with yaw 0, 45, 90 (pitch x yaw, roll x yaw, pitch x roll at yaw 0), plus a face-visibility check (hat / hair vertices over the face band, fewer than 3). FAIL when the hat gap reaches 3 % of the head width or the face is covered. `headMotionAudit(samples, specOf)` samples EVERY head of EVERY shot every `HEAD_SAMPLE_STEP` = 5 frames during the real animation (the video builds the samples with `headSampleOf(role, shot, frame, pose, bounceRock, headYaw)` while it steps its shots) and FAILS on the same limits or a pitch beyond 40 deg; it also returns a per-shot table. `HeadTurnaroundSheet` keeps the yaw-only checks.
- `HeadMotionSheet` (Studio composition, 8 characters x 8 poses: rest, look up +30, look down -30, tilt -18 / +18, shake -40 / +40, up +25 with tilt 15; men with cap and bowler, women with hat and bun, a girl with pigtails, a boy with a beanie, an elderly woman and an elderly man) logs `[qa-motion]` / `window.__qaMotion` on mount.
- Result: 520 checks over all 26 shop roles in node and 208 in Studio PASS (this passed only after the first try, a face glide of 0.10 up made hats float 3-6 %, now reduced). The sheet was LOOKED at in Studio (all 8 rows, columns up, down, tilt, tilt+, shake, up + tilt visible in the overview; the first 4 columns zoomed): hats, caps, hair, bun, pigtails and glasses stay on the head, no fringe over the face.
